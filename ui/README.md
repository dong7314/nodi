# Nodi UI

```bash
pnpm install
pnpm dev
```

개발 서버의 `/api` 요청은 `http://localhost:8787/v1`으로 전달됩니다. 백엔드 실행 방법은 [API README](../api/README.md)를 참고합니다.

## 검증

```bash
pnpm exec playwright install chromium firefox webkit
pnpm test
pnpm build
```

Playwright는 `127.0.0.1:4183`에서 실제 React·BlockNote 화면을 열고, 테스트마다 별도의 브라우저 컨텍스트와 저장 공간을 사용합니다. HTTP·WebSocket 서버는 `e2e/workspace-fixture.ts`에서 대체하므로 실제 계정이나 API 서버가 필요하지 않습니다. 이 테스트는 프론트엔드 동작과 저장 요청을 검증하며, 실제 백엔드 연동 테스트를 대신하지 않습니다.

## 페이지 본문 덮어쓰기 수정 (2026-10-02)

메인 에디터는 여러 페이지에서 재사용됩니다. 기존에는 `replaceBlocks`로 다른 페이지를 불러오는 동작도 같은 실행 취소 기록에 쌓였습니다. 페이지 2 편집 → 페이지 1 편집 → 실행 취소를 반복하면 페이지 2의 본문이 페이지 1 에디터에 복원되고, 자동 저장이 이를 페이지 1 내용으로 저장하는 문제가 있었습니다.

`src/editor-document.ts`는 문서를 불러올 때 해당 교체를 편집 기록에서 제외하고 기존 실행 취소·다시 실행 기록만 초기화합니다. 다른 에디터 플러그인과 문서 내용은 유지합니다. 실행 취소는 현재 페이지를 불러온 뒤 수행한 편집에만 적용하며, 이전 페이지에 돌아오면 새 편집 기록을 시작합니다. 사용자에 의한 블록 삭제·붙여넣기·변환 등은 기존처럼 실행 취소할 수 있습니다.

`App.tsx`에서는 페이지 ID와 에디터 문서의 소유 페이지를 확인한 뒤 저장합니다. 지연된 제목 저장과 실시간 편집 전송은 요청을 만든 페이지 ID를 사용하며, 페이지를 떠나기 전에 대기 중인 실시간 편집을 전송합니다. 늦게 도착한 조회 응답은 조회 중 발생한 로컬 편집을 덮어쓰지 않습니다. 공유 권한 해제로 홈으로 전환할 때도 에디터 본문을 함께 교체합니다.

서버 전체 스냅샷을 적용할 때도 문서 교체를 실행 취소할 수 없도록 처리합니다. 다른 사용자의 개별 블록 변경은 실행 취소 기록에서 제외하되 자신의 다른 블록 편집 기록은 유지합니다.

`e2e/page-isolation.spec.ts`는 다음을 검증합니다.

- 페이지 2 → 페이지 1 이동 후 반복 실행 취소·다시 실행과 저장 데이터 분리
- 빠른 페이지 이동 중 제목·설정·본문 보존
- 초기 서버 로딩과 백그라운드 갱신이 실행 취소 기록에 들어가지 않는지 확인
- 늦은 서버 응답과 로컬 편집의 경합
- 공유 권한 해제 후 홈 저장, 다른 사용자의 블록 편집 보존
- 페이지를 떠날 때 대기 중인 실시간 편집이 원래 페이지로 전송되는지 확인
- 브라우저 뒤로가기와 새로고침 후 각 문서 보존

## 추가 기능 점검 (2026-10-02)

원래 UI를 유지한 상태에서 저장·탐색·공유·휴지통·인라인 DB·미리보기의 상태 변경 경로를 점검했습니다. 아래 7개 문제는 수정 전 Chromium에서 재현했으며, 재현 절차를 회귀 테스트로 남겼습니다.

| 문제 | 발생 조건 | 수정 |
| --- | --- | --- |
| 휴지통 복원 실패 | 본문 저장과 삭제로 서버 revision이 바뀐 뒤 복원 | 성공한 저장마다 서버 스냅샷과 로컬 revision을 갱신하고, 복원은 대기 요청 완료 후 최신 revision 사용 |
| 최신 내용이 오래된 목록으로 교체 | 공유 목록 요청 중 다른 페이지를 열어 편집한 뒤 늦은 응답 도착 | 미저장 초안, 더 최신 서버 버전, 요청 후 생성된 페이지를 보존하며 목록 병합 |
| 표 수정 내용 유실 | 표 셀 편집 후 500ms 이내에 다른 페이지로 이동 | 에디터 해제 시 대기 변경 전송, 돌아온 에디터의 조회는 앞선 저장 완료 후 실행 |
| 표의 마지막 수정이 이전 수정으로 변경 | 느린 저장 요청 중 다시 편집하여 요청 두 개가 겹침 | DB별 요청 직렬화, 저장 응답 revision을 다음 요청에 반영 |
| 미리보기 수정 내용 덮어쓰기 | 현재 페이지를 ‘옆에서 열기’로 수정하고 본문 창에서 저장 | 제목·본문을 두 편집 화면에 함께 반영하고 외부 갱신은 미리보기에도 적용 |
| 잠금 해제 불가 | 잠긴 페이지에 다시 진입 | 본문은 읽기 전용으로 유지하면서 편집 권한이 있는 사용자의 설정 진입 허용 |
| 복제한 표가 빈 표로 생성 | 표를 포함한 블록 선택 후 복제 | 새 DB ID에 행·속성·뷰 상태를 복사. 다른 페이지에 붙여넣을 때도 별도 ID와 데이터 사용 |

추가로 공유 목록 객체가 갱신될 때마다 WebSocket을 재접속하던 동작을 줄였습니다. 실제 현재 페이지의 공유 여부가 바뀔 때만 연결을 재평가합니다. DB의 원격 갱신과 revision 충돌은 작성 중인 초안을 서버 내용으로 대체하지 않으며, `nodi:database-draft:<id>`에 초안을 보관해 페이지를 다시 열 때 복원합니다. 초기 DB 조회가 완료되기 전에는 셀 편집을 막습니다.

`e2e/workspace-races.spec.ts`는 위 재현 사례 외에 표 저장 충돌 후 초안 복원, 원격 갱신 중 초안 보존, 편집 직후 원래 값으로 되돌린 셀, 페이지 간 표 복사와 원본 분리를 확인합니다. `e2e/workspace-flows.spec.ts`는 폴더·페이지 생성, 검색, 즐겨찾기, 선택한 문서의 영구 삭제, 실시간 보기 권한 전환을 검증합니다. 기존 회귀 사례와 아래 추가 검증을 함께 실행합니다.

## 저장 충돌·입력·첨부 추가 보완

- 표는 마지막 서버 상태, 로컬 초안, 최신 서버 상태를 비교합니다. 서로 다른 셀·행·속성 변경은 자동 병합하고, 같은 값의 충돌은 표의 ‘변경 비교’에서 선택합니다. 선택 도중 서버가 다시 변경되면 최신 값으로 다시 비교합니다.
- 행 삭제·휴지통 이동과 동시 편집은 별도 충돌로 처리합니다. 열 삭제·유형 변경과 해당 열의 셀 수정이 겹치면 표 전체를 비교하도록 표시해 숨겨진 데이터 유실을 방지합니다.
- 초안과 기준 상태를 로컬에 함께 보관합니다. 저장 실패 시 ‘다시 시도’를 제공하며, 연결 복구 시 재시도합니다. 초기 조회 실패도 화면에서 재시도할 수 있습니다. 읽기 권한만 있는 사용자는 충돌을 저장할 수 없습니다.
- PostgreSQL JSONB가 객체 키 순서를 바꾸어 반환해도 같은 데이터로 비교합니다. 실제 서버 연동에서 발생하던 표의 반복 저장·불필요한 revision 충돌을 방지합니다.
- 한글 조합 중 Enter·Escape·방향키를 앱 단축키로 처리하지 않습니다. `isComposing`과 Safari의 `keyCode=229`를 함께 확인합니다.
- 파일 붙여넣기·드롭은 각 업로드를 시작한 페이지와 블록에 연결합니다. 업로드 도중 페이지를 이동하거나 미리보기를 닫아도 원래 페이지에 반영하고, 지워진 블록은 되살리지 않습니다. 업로드 실패 시 빈 임시 블록만 제거합니다.

기본 Playwright 설정은 Chromium·Firefox·WebKit의 데스크톱 검증과 Pixel 7·iPhone 13 크기의 터치 검증을 실행합니다. 조합 키 이벤트, 모바일 탐색·뒤로가기·잠금 해제, 저장 실패 후 10분 경과 및 새로고침을 거친 표 초안 복구, 충돌 선택·재충돌, 업로드 실패도 포함합니다.

### 실제 API·MinIO 브라우저 통합 검증

```bash
# api 디렉터리에서
# Docker Compose v2 사용 시 docker-compose 대신 docker compose 사용 가능
# 로컬 18787(API), 19000(MinIO), 4184(UI) 포트 사용
docker-compose -f compose.e2e.yaml up --build -d --wait

# ui 디렉터리에서
pnpm exec playwright test -c playwright.integration.config.ts

# 종료 후 api 디렉터리에서 테스트 컨테이너와 임시 데이터 제거
docker-compose -f compose.e2e.yaml down -v
```

`nodi-browser-tests` 전용 PostgreSQL·MinIO를 메모리 볼륨으로 실행하며 개발/운영 데이터베이스에는 연결하지 않습니다. 테스트 계정도 해당 서버에만 생성됩니다. 실제 API·쿠키·WebSocket·MinIO를 사용하여 다음을 각 데스크톱 엔진에서 확인합니다.

- 기존 파일 선택 창과 붙여넣기를 통한 한글 파일명 이미지·문서 업로드, 바이트 단위 다운로드 일치, 미인증 접근 차단, 새로고침 후 첨부 표시
- 서로 다른 사용자 세션 두 개의 표 동시 편집, 다른 셀 자동 병합, 같은 셀 충돌 해결, 원격 화면 반영, 불필요한 반복 저장 방지
- 업로드 완료 전 페이지 이동 및 미리보기 닫기 후 원래 페이지에 첨부 보존

WebKit 검증은 설치된 Safari 자체의 검증과 같지 않습니다. 모바일은 화면 크기·터치 에뮬레이션이며, 한글 조합은 합성 키 이벤트를 사용합니다. 실제 휴대폰·운영체제 입력기와 수일간의 오프라인 사용까지 검증한 것으로 해석하면 안 됩니다. 네트워크 복구 검증은 표 초안에 대한 것이며 앱 전체를 완전한 오프라인 제품으로 변경하지 않았습니다.

2026-10-02 앞선 보완 단계 검증: 프론트 회귀 142개(데스크톱 3개 엔진 및 모바일 터치 에뮬레이션), 실제 API·MinIO 연동 15개가 통과했습니다. `pnpm build`, PostgreSQL 통합 테스트, `go test -race`, `go vet`도 통과했습니다. 빌드에는 기존 대형 번들 경고가 남아 있습니다.

## 재검토 후 저장·접근·성능 보완 (2026-10-02)

- 실시간 본문 저장은 `mutationId`로 해당 탭의 요청 응답을 식별합니다. 같은 계정의 다른 탭 변경도 적용하고, 먼저 도착한 응답이 더 최신 입력의 보호를 해제하지 않습니다. 본문이 같은 저장 응답은 에디터·실행 취소 기록을 교체하지 않습니다.
- 초기 조회와 문서의 버전 충돌은 기준 상태·로컬 초안·서버 상태를 비교합니다. 다른 필드의 변경을 보존하고 겹친 변경은 페이지에서 ‘내 변경 저장’ 또는 ‘서버 내용 사용’으로 해결합니다. 한 문서의 충돌이 다른 문서 저장을 중단하지 않습니다. `nodi:page-draft:<id>`에 기준과 초안을 함께 보관해 새로고침 후에도 선택할 수 있습니다.
- 로그아웃 시 활성 작업 공간 캐시를 계정별로 분리하고 게스트 화면에서는 개인 문서를 표시하지 않습니다. 같은 계정으로 다시 로그인하면 보관한 초안을 복원하며, 로그아웃 후 작성한 게스트 메모도 가져오기 대상으로 유지합니다. 백업이나 복원에 필요한 저장 공간이 부족하면 원본을 유지하고 전환을 중단합니다. 초기 격리가 실패하면 개인 문서 에디터를 열지 않으며, 복원된 계정 캐시의 중복 사본은 제거합니다. 로컬 캐시는 암호화 저장소가 아닙니다.
- 페이지 목록은 서버의 모든 `nextCursor`를 따라 조회합니다. 폴더는 수정한 필드만 PATCH합니다. 검색 결과의 회원에게 바로 공유할 수 있고 초대 회원의 댓글 권한은 서버 공유 관계로 판단합니다.
- 미리보기 붙여넣기와 프리셋 적용에도 표 데이터·ID를 독립 복제합니다. 프리셋의 원본 표 캐시가 없으면 서버에서 조회하며 접근 불가 또는 조회 중 페이지·편집 변경 시 현재 내용을 유지합니다.
- 하위 페이지 링크들은 하나의 제목 스냅샷을 공유하고 본문 저장 이벤트에서 전체 워크스페이스를 링크마다 파싱하지 않습니다. 표 병합은 Map/Set 인덱스를 사용해 행 수에 비례하는 조회를 수행합니다.

`e2e/review-sync.spec.ts`는 같은 계정의 복수 세션, 지연된 저장 응답, 로딩 중 입력, 문서별 충돌과 선택·새로고침, 로그아웃·게스트 메모, 501개 페이지를 검증합니다. `e2e/editor-review-regressions.spec.ts`는 미리보기·프리셋 복제, 공유 검색, 초대 회원 댓글, 링크 제목 갱신·파싱 횟수를 확인합니다. `e2e/database-merge.spec.ts`에는 대용량 행 병합의 조회 횟수와 다수 휴지통 충돌 선택 검증을 추가했습니다.

비밀번호 설정은 UTF-8 기준 72바이트 상한을 검사합니다. 서버에서 모든 세션이 폐기되기 전에 로컬 초안을 백업하고, 변경 후 로그아웃 완료를 기다립니다. `e2e/account-password.spec.ts`는 초과 입력·정확한 바이트 경계·초안 백업·로그아웃·백업 실패를 확인합니다. `e2e/workspace-cache.spec.ts`는 실제 브라우저 저장 용량 초과, 복원 실패의 원상 복구, 중복 캐시 공간 회수, 로그아웃 중단과 개인 캐시 노출 차단을 검증합니다.

## 하위 페이지의 회원 공유 상속 (2026-10-03)

- 상위 페이지에 초대한 회원은 기존·새 하위 페이지와 그 아래 페이지에도 같은 보기·편집 권한으로 접근합니다. `/page`로 공유 편집자가 생성한 문서도 부모 소유자 아래에 유지됩니다. 공유 패널은 상속 출처를 표시하고, 상속만 받은 회원의 제거는 상위 페이지에서 처리하도록 안내합니다.
- 하위 페이지에 별도 편집 권한을 추가할 수 있으며, 직접 공유 해제 뒤에도 상속 권한이 있으면 이를 표시합니다. 공유 변경 후 전체 공유 목록을 갱신하고, 변경 전에 시작된 지연 응답이 최신 권한을 덮어쓰지 않게 합니다.
- 다른 세션이 만든 하위 페이지 링크가 아직 로컬 목록에 없어도 클릭 시 서버에서 읽어 미리보기를 엽니다. 조회 도중 다른 페이지로 이동하거나 계정이 바뀌면 이전 요청으로 미리보기를 열지 않습니다.
- 공개 링크는 기존 페이지별 공개 설정을 유지합니다. 회원 공유 상속에는 서버의 `006_inherited_page_shares.sql` 마이그레이션이 필요합니다.

`e2e/inherited-sharing.spec.ts`는 상속 출처와 관리 버튼, 상속된 보기 권한에 별도 편집 권한 추가, 지연된 공유 목록 응답, 아직 목록에 없는 하위 페이지 조회·저장과 탐색 취소를 확인합니다. `integration/storage.spec.ts`는 실제 두 계정에서 소유자와 공유 편집자가 각각 `/page`로 생성한 문서의 자동 공유, 다른 계정에서 열기, 상위 권한 축소·해제를 검증합니다.

실제 API·MinIO 연동 27개가 Chromium·Firefox·WebKit에서 통과했습니다. 하위 페이지의 첨부 업로드·다운로드와 상위 공유 해제 후 다운로드 차단도 포함합니다. 백엔드 전체 `go test -race -count=1 ./...`, `go vet ./...`가 통과했으며, 첨부 권한 및 본문 없는 종료 이벤트 검사는 각각 15회 반복 통과했습니다. 종료 이벤트 검사는 초기 presence 완료를 기다리도록 해 연결 초기화와 삭제가 경합해 소켓이 먼저 닫히는 경우를 분리했습니다.

최종 소스로 전체 프론트엔드 회귀 472개가 12분에 모두 통과했습니다(Chromium·Firefox·WebKit·모바일 포함). `pnpm build`와 `git diff --check`도 통과했으며 기존 대형 번들 경고는 유지됩니다.

## Push 전 최종 리뷰 보완 (2026-10-04)

- 홈에서 `/page`를 만들면 서버의 일반 페이지 테이블에 없는 `quick-note`를 부모로 보내 404가 발생했습니다. 새 문서는 개인 최상위 페이지로 저장하고 홈 본문의 링크는 유지합니다. 기존 로컬 데이터의 잘못된 홈 부모 참조도 정규화합니다.
- 첫 생성 요청이 완료되기 전에 새로고침하면 초기 서버 목록에 없는 새 문서를 삭제된 페이지처럼 버렸습니다. 서버 revision이 없는 생성 중인 문서는 로컬 초안으로 유지하고 생성·저장을 다시 시도합니다. 이미 서버에서 삭제된 기존 revision 문서는 이 경로로 복구하지 않습니다.
- 본문 저장은 가능하지만 표 캐시·초안 저장만 실패하는 경우, 로그인·로그아웃이 오래된 셀 내용을 가져오거나 백업할 수 있었습니다. 실패한 표 스냅샷과 초안을 계정에 연결된 메모리에 보관하고, 계정 전환 전에 다시 저장합니다. 저장 실패 시 전환을 중단하며, 권한이 일시적으로 보기 전용으로 바뀌었다 돌아와도 메모리 초안을 복구합니다. 메모리 보관은 브라우저 종료를 견디는 영구 저장은 아닙니다.

회귀 검사는 `guest-auth-preservation.spec.ts`, `database-snapshot-boundaries.spec.ts`, `pending-page-creation.spec.ts`, 실제 서버의 홈 `/page` 생성·재조회 사례에 추가했습니다.

실제 API·PostgreSQL·MinIO 연동 30개가 Chromium·Firefox·WebKit에서 통과했습니다. 첫 전체 실행에서 Firefox 홈 생성 검사가 앞선 실행의 하위 페이지 링크를 클릭해 미리보기를 여는 문제가 있어, 검사별 홈 본문을 준비하고 해당 문단에 커서를 놓도록 고친 뒤 30개 전체를 다시 통과했습니다.

전체 프론트엔드 484개 실행에서는 483개가 통과했고, WebKit 로그아웃 검사의 일시적인 알림 문구 확인이 1개 실패했습니다. 5회 반복에서도 1회 재현됐으며, 비동기 503 저장 실패 알림과 검사 시점이 겹쳤습니다. 해당 검사는 로그아웃 확인창 종료, 지속되는 저장 실패 상태, 편집 가능한 최신 본문, 세션·기존 캐시 유지와 로그아웃 요청 미전송을 확인하도록 보완했습니다. 애플리케이션 코드는 변경하지 않았으며 `workspace-cache.spec.ts` 전체를 세 브라우저에서 각각 3회 반복해 63개 모두 통과했습니다. `pnpm build`, 백엔드 전체 race 테스트·vet, `git diff --check`도 통과했습니다. 기존 대형 JavaScript 번들 경고는 유지됩니다.
